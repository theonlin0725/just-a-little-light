## 2. 前置条件

| 项 | 要求 |
| --- | --- |
| 微信开发者工具 | 稳定版，登录你的微信号 |
| 小游戏 AppID | 微信公众平台 → 小游戏 → 开发管理 → 开发设置 |
| 项目成员权限 | 你的微信号是该 AppID 的开发者/管理员 |
| 激励视频广告位 | 流量主后台创建，属于该 AppID（没有也能玩，只是广告不可用） |
| Base Library | ≥ 2.32.3 |
| Node | ≥ 18（构建用） |

## 3. 配置

编辑 `config/wechat.config.json`：

```json
{
  "appid": "wx1234567890abcdef",
  "adUnitId": "adunit-xxxxxxxxxxxx",
  "libVersion": "2.32.3"
}
```

- `appid`：小游戏 AppID。留空时产物是 `touristappid`，只能本地导入，不能上传。
- `adUnitId`：激励视频广告位 ID。留空时广告返回「暂不可用」，其余玩法不受影响。
- 敏感信息（上传私钥、AppSecret）不要写进这个文件，也不要提交。
- 也可以用环境变量覆盖：`WX_APPID=wx... WX_AD_UNIT_ID=adunit-... npm run build:wechat`。

## 4. 构建

```bash
npm install            # 只为构建工具 esbuild；游戏运行时不依赖它
npm run build:wechat   # 一次产出 wechat/（正式）+ wechat-dev/（QA）
npm run verify:wechat  # 包结构、buildId、sha256、QA 入口、AppID
```

产物：

```
wechat/          正式包：minify，QA 入口被替换成空模块 —— 导入 / 上传用这个
  game.js
  game.json
  project.config.json
  build-info.json

wechat-dev/      QA 包：不压缩，带跳关 / 解锁 / 模拟奖励 —— 只用于自测，不要上传
```

- 当前正式包约 108 KB，远低于主包 4 MB 限制，不需要分包。
- `buildId` 是 bundle 的 sha256 前 12 位，会写进 `build-info.json` 和包内日志，用来对齐「你测的是哪个包」。
- `wechat-dev/` 没有提交到仓库；需要时本地构建。

## 5. 导入开发者工具

1. 打开微信开发者工具 → 导入项目。
2. 目录选 `wechat/`（**不是仓库根目录**）。
3. AppID 填你自己的小游戏 AppID；项目类型会自动识别为「小游戏」（`compileType: game`）。
4. 详情 → 本地设置：不需要勾选 ES6 转 ES5（产物已经是 ES2017 的单文件 IIFE）。
5. 模拟器应直接进入首页；点「开始 / 继续」可玩。

## 6. 真机自测清单

> 自动化能覆盖逻辑和交互层，但覆盖不了手感、声音、遮挡和真实广告。

### 基础

- [ ] 冷启动无白屏/黑屏，首页标题、底栏五个图标正常。
- [ ] 第 1 关：拖动跟手，水晶亮起，保持 3 秒通关；松手不粘手。
- [ ] 面板/选关/广告/切后台后再回来，计时没有跳变、没有直接通关。
- [ ] 杀进程重进：进度、解锁、皮肤都还在。

### 双光源 / 双侧

- [ ] 第 25、27 关：两盏灯依次拖动；「带两个点的水晶」要两盏灯同时照。
- [ ] 第 37 关：上下两侧同时亮；第 38 关不再显示教学。
- [ ] 第 49、59、60 关：双灯 + 双侧 + 移动 + 干扰叠加。

### 皮肤 / 广告

- [ ] 皮肤可预览、解锁、切换；关闭后立即生效。
- [ ] 看完广告才发奖；提前关闭不发奖；无填充时有提示。
- [ ] 没有广告位时，提示面板不诱导点击必然失败的入口。

### 适配

- [ ] 刘海/挖孔屏：HUD、底栏、弹窗不进入遮挡区。
- [ ] 窄屏（360 CSS 宽）五个热区不重叠。
- [ ] 长屏（844 高）上下光柱不被拉成一条细缝。
- [ ] 低端 Android：帧率、光晕、阴影是否可接受。

### 音频

- [ ] BGM 不吵、不低频轰鸣；音乐/音效开关独立。
- [ ] 水晶「叮」可听；保持时的「滋滋」不刺耳；通关音不爆音。
- [ ] 切后台 30 秒回来，不会叠多份 BGM。

## 7. 广告接入说明

代码在 `src/ads.js`，两个 provider：

- `simulated`：浏览器用，4.5 秒假播放器，带进度条；
- `wx`：微信用，`wx.createRewardedVideoAd`。

规则：

- 只有 `isEnded === true` 才发奖；取消、未看完、无填充、超时都不发。
- 广告期间冻结关卡仿真、计时、保持进度。
- 切关/重开会使旧回调失效（令牌校验），不会误伤新关卡。
- `adUnitId` 为空时，直接返回「广告暂不可用」，不创建广告实例。

**尚未验证**：真实广告位的 eCPM、填充率、审核政策、激励视频在 iOS/Android 的差异。需要你用自己的流量主后台配置后真机测试。

## 8. 存档

- 浏览器：`localStorage`，键 `projection.save.v3`。
- 微信：`wx.setStorageSync`，同一个键。
- 兼容 v1/v2：`unlocked`、`best` 原样迁移；旧版只到 36 关时，用「已通关的最高关卡」兜底修正，不会卡在第 37 关。
- 皮肤解锁/装备一起持久化。
- 体验版和正式版可能共享同一份存储；测试跳关请用 `wechat-dev/`，不要用正式包。

## 9. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 打开黑屏 | 在 `wx.createCanvas()` 之前创建了别的离屏画布 | 检查 import 阶段是否建 canvas（本项目没有） |
| 触摸位置偏移 | 布局 scale/offX/offY 与实际显示区不一致 | 断点看 `layout()`，或打开 QA 的 `__qa.layout()` |
| 广告一直「暂不可用」 | `adUnitId` 为空 / 未开通流量主 / 广告位与 AppID 不匹配 | 看控制台 `[ads]` 日志与 `onError` 的 errCode |
| 上传提示 AppID 无效 | 用了 `touristappid` 或 AppID 类型不是小游戏 | 换成小游戏 AppID，确认「开发管理」里是 game 类型 |
| 真机帧率低 | `shadowBlur` / 光晕 / 尘埃 | 先降画质档位，不要动几何判定 |
| 音效没有声音 | 基础库 < 2.19 / 静音 / 用户没交互 | 音频会自动降级；检查开关与系统静音 |

## 10. 发布前还要做什么

这不是一份「审核一定能过」的承诺，只是工程清单：

- [ ] 用你自己的 AppID 重新构建（不要直接用仓库里的产物上传）。
- [ ] 配置真实广告位，真机验证发奖/取消/无填充。
- [ ] 隐私协议、用户信息收集说明（本项目不收集个人信息，但平台要求仍需确认）。
- [ ] 软著/备案/类目等资质，按微信公众平台当前要求准备。
- [ ] 真机多机型测试：至少一台 iOS、一台 Android、一台低端机。
- [ ] 版本号、更新说明、体验成员名单。
- [ ] 提审前用 `wechat/`，不要用 `wechat-dev/`。
