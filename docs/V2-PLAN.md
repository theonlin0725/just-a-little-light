# Version 2 方案：让 40 秒变成 3 分钟

> **状态：设计提案，未实现。** 当前仓库代码仍是 v0.5（60 关、471 项测试、微信包 108 KB）。
> 这份文档基于你收集到的用户反馈，以及 2026-11 的讨论整理；它不是「再加 60 关」，而是把游戏从「一次解谜」改成「一场有节奏的追光」。
>
> 本方案取代 `docs/ROADMAP.md` 里的 v1.1–v1.3 轻量设想；ROADMAP 保留为早期版本，实际执行以本方案为准。

---

## 0. 一页结论

### 0.1 诊断：用户不是玩腻了，是没被接住

40–60 秒的停留，通常不是「关卡太长/太短」，而是五个流失点叠加：

| # | 流失点 | 用户心里的原话 | 现在的设计 |
| --- | --- | --- | --- |
| 1 | 不知道怎么玩 | 「我要把这个球拖去哪？」 | 第一关只有一行字，没有手把手 |
| 2 | 没有下一步 | 「过了一关，然后呢？」 | 只有「下一关」，没有星级/货币/章节 |
| 3 | 3 秒是空白 | 「找到了，然后等 3 秒」 | 3 秒是进度条，不是玩法 |
| 4 | 关卡同质 | 「怎么又是拖到下面某个位置」 | 60 关共用一条难度轴 |
| 5 | 没有回来的理由 | 「明天再玩也行」 | 没有每日、收藏、社交、故事 |

### 0.2 三个抓手

1. **接住**：前 3 分钟用「做」来教，不用文字教；第一次通关在 30 秒内发生。
2. **留住**：给一个 3–5 分钟的 session 剧本——教学 → 首胜 → 首星 → 章节宝箱 → 第一套皮肤。
3. **玩深**：把「找位置」升级成「找路径 + 找时机」；让 3 秒从等待变成维持。

### 0.3 核心改动

| 模块 | v0.5 | V2 |
| --- | --- | --- |
| 新手引导 | 一行字 + 直接进关 | 三步交互引导 + 幽灵手指 + 无失败教学 |
| 前 20 关 | 现有玩法 | **保留机制，重做引导/星级/计时** |
| 21–29 关 | 旧机制延伸 | **过渡章：旧机制 + 时间 + 边缘移动** |
| 30–60 关 | 旧机制组合 | **镜面反射 / 棱镜分光 / 旋转与移动 / 终章** |
| 时间 | 无 | **20 秒基础时限；全亮触发 3 秒时冻结** |
| 3 秒 | 等待进度条 | **维持阶段：世界在变，玩家要持续调整** |
| 反馈 | 通关 / 下一关 | **星级 + 光尘 + 章节宝箱 + 商城** |
| 商业化 | 广告位未配置 | **激励视频打通：双倍光尘 / 提示 / 皮肤试用 / 每日宝箱** |
| 沉浸 | 单关体验 | **星座地图 + 无字叙事 + 分层音乐 + 触觉** |

### 0.4 目标（假设，需埋点验证）

| 指标 | 现在 | V2 目标 |
| --- | --- | --- |
| 平均 session | 40–60 秒 | **3–5 分钟** |
| 单 session 关卡数 | 1–2 关 | **5–8 关** |
| 教学完成率 | 未知 | **≥ 85%** |
| 第 5 关到达率 | 未知 | **≥ 70%** |
| D1 | 未知 | **≥ 35%** |
| D7 | 未知 | **≥ 12%** |
| 首套皮肤获得 | 看广告/几乎无 | **前 3 次 session 内 ≥ 40%** |
| 激励视频观看率 | 0（未打通） | **15%–25%** |

> 这些数字是目标，不是承诺。V2 的第一件事是埋点，把「40–60 秒」拆成可解释的漏斗。

## 1. 诊断：40–60 秒到底丢在哪

### 1.1 现在的循环

```
打开 → 首页 → 第 1 关 → 拖光 → 3 秒 → 通关 → 下一关 → …
```

这个循环里，**玩家每 30 秒才获得一次反馈**（通关），而且反馈只有「下一关」。对短视频/小游戏用户来说，30 秒没有新信息，就会退出。

> **用户原话（节选）**
>
> - 「前期关卡缺乏引导关：用户进去之后其实不知道该怎么样移动光源，以及要达成什么样的目标才能通关。」
> - 「目前已有的玩法主要是移动光源、移动双光源、躲避障碍物，以及延时 3 秒通关……后面 30 关到 60 关需要重新设计。」
> - 「现在这 60 关从用户体验上来讲，其实都更方便通关，因为手指只需要在屏幕下方移动。」

这三句话分别对应：**不会玩、太单一、太舒服**。V2 的三个抓手就是对着这三件事去的。

### 1.2 五个流失点的设计对策

| 流失点 | 不是…… | 而是…… | 对策 |
| --- | --- | --- | --- |
| 不会玩 | 玩家笨 | 第一关没有「必须做对」的引导 | 三步交互教学，第一步就必须拖动 |
| 没目标 | 玩家没耐心 | 通关后没有可见的下一目标 | 星级、光尘、章节宝箱、皮肤进度 |
| 3 秒空白 | 玩家嫌慢 | 找到答案后没有新决策 | 让障碍/镜子在保持期间继续动 |
| 关卡同质 | 玩家喜新厌旧 | 60 关只有一条「找位置」轴 | 位置 → 路径 → 时机/颜色 |
| 不回来 | 玩家不忠诚 | 没有每日理由和收藏 | 每日星图、星座、皮肤、回声 |

### 1.3 一次 3–5 分钟的 session 剧本

这是 V2 最重要的设计物：**第一会话的逐分钟脚本**。

| 时间 | 发生什么 | 玩家获得 |
| --- | --- | --- |
| 0–10s | 首页只有一个「开始」；点开后直接进入第 1 关，幽灵手指拖动光球 | 「原来是这样拖」 |
| 10–30s | 第一颗水晶亮起，3 秒环出现，通关；光尘 +10，星级 +1 | 第一次「我做到了」 |
| 30–60s | 第 2 关教影子；第 3 关教双目标；每关 20–30 秒 | 连续三次小胜利 |
| 60–90s | 第 4 关移动障碍；首次三星；光尘约 90；商城图标出现红点 | 「我可以买点什么」 |
| 90–150s | 第 5–6 关；失败一次，1 秒内重试；第一次想「再来一次」 | 紧张感 + 掌控感 |
| 150–210s | 第 7–8 关；用 120 光尘买下「微光」拖尾并装备 | 第一次收藏/个性化 |
| 210–270s | 第 9–10 关；第 1 章宝箱 +100；星座第一段连线 | 第一次「章节完成」 |
| 270–300s | 回主页看星座图；「明日星图」预告；第一套皮肤还差一点光尘 | 「明天再来」 |

> 这张表是目标节奏，不是硬性脚本。关键是：**3 分钟内至少有 1 次三星、1 次购买、1 次章节反馈**；否则用户没有理由留下。

**关键**：不是把每关做长，而是把「下一个反馈」的间隔压到 20–30 秒，并在 3 分钟内给一次「大反馈」（宝箱/皮肤）。

### 1.4 目标用户与场景

| 用户 | 场景 | 他们想要 | V2 对应 |
| --- | --- | --- | --- |
| 碎片玩家 | 地铁/电梯/排队，1–3 分钟 | 点开就会、每关短、随时能停 | 三步教学、20–30 秒关、自动下一关、断点续玩 |
| 解谜爱好者 | 晚上 10–20 分钟 | 新机制、难度、可钻研 | 镜子/棱镜、三星、挑战模式、回声 |
| 收藏/分享型 | 微信聊天/朋友圈 | 好看、有战绩、能晒 | 光尘商城、皮肤、星座、分享卡 |

> 先服务「碎片玩家」把留存跑通，再服务「解谜爱好者」做深度；不要一开始就为硬核玩家把关卡做难。

## 2. 核心设计：一个动作，三种深度

### 2.1 唯一动作不变

V2 仍然只有**一根手指拖光**。不加摇杆、不加多指、不加技能按钮。

所有新机制都必须满足：

- 局内不增加按钮；
- 不要求像素级瞄准；
- 失败能说清原因；
- 手机上单手可完成。

### 2.2 三条深度轴

| 轴 | 玩家在问 | 现有 | V2 |
| --- | --- | --- | --- |
| 位置 | 我站在哪？ | 1–60 关 | 保留，前 20 关 |
| 路径 | 光怎么走？ | 只有遮挡 | **镜子反射、棱镜分光、单向玻璃** |
| 时机/状态 | 什么时候站？ | 移动障碍 | **旋转镜、移动水晶、时间窗、颜色** |

位置是二维搜索；路径是序列推理；时机是节奏判断。三条轴叠加，才有「需要构思的移动」。

### 2.3 把 3 秒从「等待」变成「维持」

这是 V2 的灵魂。

**现在的 3 秒**：找到位置 → 看着进度条走完 → 赢。玩家在这 3 秒里没有新决策。

**V2 的 3 秒**：全亮后进入「维持」阶段，世界继续变化：

- 镜子缓慢旋转，光路会偏；
- 移动障碍继续走，影子会切进来；
- 水晶会「呼吸」，亮度周期性下降；
- 干扰角色会靠近，需要微调光源；
- 计时冻结，但玩家不能松手。

结果是：**3 秒不是奖励动画，而是最后一个操作段。** 玩家在最后 3 秒仍在做判断，沉浸感来自这里。

> 设计口诀：**「找到光是开始，守住光才是通关。」**

### 2.4 六条设计原则

1. **一根手指，不加速度/摇杆。**
2. **难度来自观察与规划，不来自像素精度。**
3. **每次失败都能说出原因。**
4. **广告不挡路，货币不卖通关。**
5. **先给糖，再给挑战**：3 分钟内必须有第一次大反馈。
6. **3 秒必须是主动的**：保持阶段要有变化，不能干等。

### 2.5 有趣的本质：每 10–15 秒一次「预测 → 行动 → 反馈」

| 阶段 | 玩家做什么 | 游戏给什么 |
| --- | --- | --- |
| 预测 | 看光路/影子，猜位置 | 虚线预览、镜面角度、影子边界 |
| 行动 | 拖动光源 | 跟手、光晕、粒子 |
| 反馈 | 水晶亮/灭、音效、触觉 | 即时、可解释 |
| 新预测 | 还差一颗/时间还够吗 | 新信息，不是重复 |

如果 10 秒内没有新信息，玩家就会走。V2 的所有机制都要服务这条。

## 3. 新手引导：前 3 分钟

### 3.1 现在的问题

第 1 关的文案是「拖动光源，让墙上的水晶亮起来 / 全部点亮并连续保持 3 秒」。这句话对设计师很清楚，对第一次玩的人信息过载：

- 哪个是光源？
- 拖到哪里？
- 水晶在哪？
- 3 秒是什么？
- 为什么我拖了没反应？

**文字不是引导，动作才是。**

### 3.2 三步交互引导

| 步骤 | 玩家必须做的事 | 游戏反馈 | 文案（最多一行） |
| --- | --- | --- | --- |
| 1 拖 | 手指按住光球并移动 | 光球跟手，光晕变亮；幽灵手指淡出 | 「拖动光球」 |
| 2 亮 | 把光拖到水晶方向 | 水晶亮起，「叮」；光柱连接 | 「让水晶亮起来」 |
| 3 守 | 保持不动 3 秒 | 进度环 + 秒数；通关 | 「保持 3 秒」 |

关键细节：

- **第 1 关不放障碍、不放第二颗水晶**，让「拖 → 亮」的因果绝对清楚。
- **幽灵手指**：半透明的手，沿正确方向缓慢移动；玩家一碰屏幕就淡出，不抢操作。
- **门控**：步骤 2 不完成，不出现步骤 3 的文案；不要一次性把规则全倒出来。
- **无失败**：教学关没有计时、没有失败；拖错只出一个很轻的方向箭头。
- **可跳过**：老玩家/重装玩家点「跳过教学」，直接进第 3 关。

### 3.3 第 1–5 关脚本

| 关 | 教学目标 | 场景 | 引导 | 计时 |
| --- | --- | --- | --- | --- |
| 1 第一束光 | 拖 → 亮 | 一个光球、一颗水晶、无遮挡 | 幽灵手指 + 门控三步 | 无 |
| 2 影子 | 遮挡关系 | 一块挡板 | 幽灵手绕开挡板；失败只给箭头 | 无 |
| 3 双星 | 同时亮 | 两颗水晶 | 第一颗亮后，第二颗闪烁提示 | 无 |
| 4 呼吸 | 等窗口 | 一个移动挡板 | 挡板让开时高亮，教「等」 | 无 |
| 5 第一次挑战 | 时间压力 | 旧机制组合 | 30 秒计时；无幽灵手 | 30s |

> 用户说「前期关卡缺乏引导关」，V2 的回答不是加一段说明，而是**把第 1 关重做成一个必须动手的引导关**，并把第 5 关做成第一次「我自己做到了」的挑战。

### 3.4 无字引导与失败前进

- **无字优先**：能用光、箭头、脉冲表达的，不用文字。中文小游戏用户阅读意愿低。
- **失败前进**：教学关拖错不判失败；10 秒无操作，箭头出现；20 秒无操作，幽灵手重播。
- **一次只教一件事**：第 1 关只教拖，第 2 关只教影子，第 3 关只教多目标，第 4 关只教等窗口。
- **首胜在 30 秒内**：第 1 关的目标位置离起点很近，拖动距离 < 屏幕 1/3。

### 3.5 验收指标

- 教学三步完成率 ≥ 85%；
- 第 1 关到第 2 关的流失 < 15%；
- 第 5 关到达率 ≥ 70%；
- 首次通关时间中位数 < 35 秒；
- 「不知道怎么玩」相关反馈 < 5%。

## 4. 关卡结构：1–20 保留，21–29 过渡，30–60 重做

### 4.1 章节表

| 章节 | 关卡 | 主题 | 核心机制 | 计时 |
| --- | --- | --- | --- | --- |
| 第一章 初见 | 1–10 | 学会拖光 | 静态遮挡、单/双目标、3 秒 | 无（11 起软计时） |
| 第二章 微光 | 11–20 | 学会等 | 移动障碍、干扰角色、双光源、双侧 | 软计时 / 30s |
| 第三章 桥 | 21–29 | 旧机制极限 | 旧机制 + 边缘移动 + 20–30s | **20–30s** |
| 第四章 镜 | 30–39 | 学会折射 | 固定镜、旋转镜、单向镜 | **20–30s** |
| 第五章 棱 | 40–49 | 学会分光 | 棱镜、颜色、分色水晶 | **25–35s** |
| 第六章 时 | 50–59 | 学会共存 | 移动镜、移动水晶、影子钥匙、组合 | **30–45s** |
| 终章 星 | 60 | 收束 | 全部机制 + 星座 | **45–60s** |

> 用户建议「前 20 关保留，30–60 重做」。V2 把 21–29 做成**过渡章**：不引入新机制，只把旧机制放到边缘、加上计时，让玩家从「找位置」自然过渡到「找路径」。这样不会出现 20 → 30 的断层。

### 4.2 第一章、第二章：保留机制，重做体验

- **关卡数据尽量保留**：1–20 的几何、难度、解法不动，避免老玩家进度失效。
- **叠加新层**：教学引导、星级目标、光尘奖励、软计时（第 11 关起）。
- **重排难度**：如果第 1–5 关的原数据不适合教学，允许换顺序/微调，但必须过校验器。
- **第 10、20 关做「章节考试」**：比普通关稍难，通关给章节宝箱。

### 4.3 第三章 21–29：桥

这 9 关不引入新机制，任务是**把玩家从「底部拖光」逼到「全屏移动」**：

- 光源起点在左/右/上边缘，目标在另一侧；
- 光球沿一条轨道移动（底部弧线、L 形、环形），不是自由 2D；
- 移动障碍 + 20–30 秒时限；
- 第一次出现「时间冻结」：全亮后计时变蓝、停住，玩家第一次感受到「我抢到了」。
- 关卡命名：窄桥、逆流、回声、断点、折返、悬桥、风口、最后一秒、桥尽头。

> 如果你更想严格「只动 30–60」，21–29 可以保留现有数据，只加计时/星级；但这样 20 → 30 的机制断层会很明显，需要用 30 关的教学关来补。我的建议还是重做这 9 关，成本不高，收益是把「全屏移动」提前教会。

### 4.4 第四章 30–39：镜

新机制：**镜面反射**。

| 关 | 名称 | 机制 | 玩家要发现 |
| --- | --- | --- | --- |
| 30 | 第一面镜 | 一面 45° 固定镜 | 光可以拐弯 |
| 31 | 两次 | 两面固定镜 | 路径是折线，不是直线 |
| 32 | 镜后 | 镜子挡住直射，只能反射 | 直射被挡时，找镜像光源 |
| 33 | 转镜 | 缓慢旋转的镜子 | 等一个角度，再保持 3 秒 |
| 34 | 双面 | 两面镜子 + 两个水晶 | 一条光路服务两个目标 |
| 35 | 单向 | 单向镜：一面透、一面反 | 从哪边照？ |
| 36 | 窄角 | 镜面很窄，入射角窗口小 | 站位要准，但有预览辅助 |
| 37 | 移动镜 | 镜子沿轨道移动 | 等镜子走到位 |
| 38 | 镜与影 | 镜子 + 挡板影子 | 反射路径也会被影子挡 |
| 39 | 镜之试 | 综合 | 先规划路径，再落点 |

**教学节奏**：30 教「光会拐弯」；31 教「路径是折线」；32 教「直射被挡时用镜像」；33 教「等角度」；34–39 练习/变奏/考试。

### 4.5 第五章 40–49：棱

新机制：**棱镜分光 / 颜色**。

| 关 | 名称 | 机制 | 玩家要发现 |
| --- | --- | --- | --- |
| 40 | 分叉 | 棱镜把一束光分成两束 | 一束光可以同时服务两个目标 |
| 41 | 三色 | 红/蓝/黄滤片 | 水晶只吃对应颜色 |
| 42 | 混色 | 两束光重叠成新颜色 | 位置决定颜色 |
| 43 | 缺一 | 三颗水晶，只有两种颜色 | 先满足稀缺色 |
| 44 | 分光镜 | 棱镜 + 镜子 | 分光后再反射 |
| 45 | 颜色影子 | 滤片 + 遮挡 | 颜色也被影子影响 |

### 4.9 关卡生产管线

V2 的关卡不能手摆，尤其是镜面关。管线：

```
设计意图（这道题问什么）
   ↓
关卡配方 / 编辑器
   ↓
求解器：搜索光源位置/镜子角度/时间窗口
   ↓
校验器：可解、开局不自动通关、解区面积、时间预算、3 秒窗口
   ↓
审查器：与相邻关的解法相似度、动作向量
   ↓
人工试玩：读不读得懂、有没有「啊哈」
```

镜面关的求解器：

- 光源位置：在可拖拽区网格采样；
- 镜子角度：固定/旋转采样；
- 光路：射线求交 + 反射，最多 3 次反弹；
- 判定：所有水晶在 3 秒窗口内被照到；
- 时间：解区存在 + 3 秒保持 + 缓冲 ≤ 时限。

**没有求解器的关卡不进游戏。** 这是 v0.5 已经验证过的原则。

## 5. 新机制详解

### 5.1 镜子：两种实现，先做可读的那一种

用户建议「镜子可以反光、折射」，方向完全对。但「点光源 + 镜子」在手机上有一个可读性问题：点光源向四面八方发光，镜子会把光反射到很多方向，玩家很难判断「哪条光路在点亮水晶」。

有两种实现路线：

#### 路线 A：点光源 + 镜像光源（推荐先原型）

- 平面镜把点光源反射成一个**虚拟光源** `L'`，在镜子后面。
- 水晶被反射光照亮，当且仅当：`L'` 到水晶的连线穿过镜子，且路径无遮挡。
- 视觉：镜子后面出现一个淡淡的「光的倒影」，光路画成折线。
- 优点：保留现有「点光源 + 影子」的几何，老机制自然延伸；一面镜子就能做出「拐弯」。
- 缺点：多面镜子的虚拟光源会递归，需要限制反弹次数；玩家需要理解「镜子里有一个我」。

```
        L' (镜像光源)
          \
           \  镜子
            \ |
             \|
              Q
             / \
            /   \
           L     crystal
```

#### 路线 B：光束模式（备选）

- 新增「光束发射器」，只朝一个方向发一条光束；镜子反射、棱镜分光。
- 玩家拖动发射器位置，方向固定（或沿轨道切线）。
- 优点：光路极其清晰，适合做棱镜/颜色；手机上好读。
- 缺点：不再是「点光源 + 影子」，等于新增一种光源类型；需要教学。

**建议**：

- **30–39 关先用路线 A**（点光源 + 镜像），因为它是现有玩法的自然升级，也最符合用户「让现在的光反射」的直觉。
- **40–49 关的棱镜/颜色用路线 B**（光束模式），因为点光源的折射在手机上几乎不可读；把「光束」作为新章节的新玩具，而不是替换旧光。
- 如果路线 A 的试玩中，5 个玩家有 3 个看不懂「镜像光源」，立刻切到路线 B，关卡主题不变。

#### 镜子的可读性规则

- 镜子只画**反光面**，背面是暗的；反光面有高光。
- 固定镜画 45° 角标；旋转镜画一个缓慢转动的指针。
- 拖动时显示**虚线光路**；松手后变成实线。
- 镜面命中点画一个小亮斑；没有命中时不画。
- 最多 3 次反弹；超过就变暗/吸收，避免无限递归。
- 音效：镜面命中「叮」，反弹次数越多音高越高。

#### 镜子类型

| 类型 | 行为 | 用途 |
| --- | --- | --- |
| 固定镜 | 45° / 90°，不可动 | 基础路径 |
| 旋转镜 | 缓慢旋转，周期 4–8 秒 | 时间窗口 |
| 单向镜 | 一面透、一面反 | 方向判断 |
| 吸收镜 | 黑镜，光被吸收 | 排除错误路径 |
| 分光镜 | 一束变两束 | 双目标 |

### 5.2 棱镜与颜色

- **棱镜**：一束光分成两束（红/蓝），或者分成两束同色但方向不同。
- **滤片**：只让一种颜色通过；其他颜色被吸收。
- **颜色水晶**：只吃对应颜色；白色水晶吃任意颜色。
- **混色**：红 + 蓝 = 紫；黄 + 蓝 = 绿；红 + 黄 = 橙。第一版只做「两色」，不做三色混合，降低认知负担。
- **色盲友好**：颜色之外，加形状/纹理编码（圆点/斜线/三角），设置里可开「高对比模式」。
- **教学**：40 关只教「一束变两束」；41 关教「颜色匹配」；42 关才教混色。

### 5.3 影子钥匙（创意加码，成本低）

这是 V2 里我最想加的一个「便宜但有惊喜」的机制：

- 墙上有一个**符文**，只有当某个障碍物的影子**盖住它**时才激活。
- 玩家移动光源，改变影子的大小/位置；既要点亮水晶，又要让影子盖住符文。
- 它复用现有影子几何，不需要新渲染；但会让玩家第一次意识到「影子不只是挡路，还能当钥匙」。
- 例子：第 52 关「影子钥匙」——光源要同时让两颗水晶亮着，并让柱子的影子盖住下面的符文；影子太小/太大都不行。
- 风险：影子边界要清晰；用虚线描出符文和影子边缘；不要让玩家靠猜。

### 5.4 移动镜 / 移动水晶

- **旋转镜**：周期 4–8 秒，光路周期性扫过水晶；玩家要等一个窗口，再保持 3 秒。
- **移动水晶**：水晶沿墙来回移动；玩家要跟住它 3 秒；光源拖动要平滑。
- **移动镜 + 移动水晶**：两个周期错开，找共同窗口；第 53、57 关。
- **设计底线**：周期可见、可预判；不要在屏幕外突然变化；不要用随机。

### 5.5 边缘移动与轨道

用户指出「现在手指只需要在屏幕下方移动」。V2 用四种方式逼玩家用全屏：

1. **光源起点在边缘**：左/右/上边缘开始，目标在另一侧；玩家必须横跨屏幕。
2. **轨道移动**：光源沿一条可见轨道移动，轨道可以是底部弧线、L 形、环形、S 形；玩家拖的是「沿轨道的进度」，不是自由 2D。
3. **多光源分区**：两盏灯分别在左上/右下，玩家要来回切换；点哪盏拖哪盏。
4. **墙面方向变化**：大部分关是上下墙；部分关改为左/右墙或三面墙，光柱从不同方向接入。进入时给一个短镜头旋转提示，避免迷失。

轨道的好处：

- 手指不需要精确 2D 定位，降低误触；
- 轨道形状本身就是关卡设计变量；
- 玩家必须移动手，视觉上更「动」；
- 可以做「轨道 + 镜子」的组合。

**不要做**：全屏自由拖 + 小目标 + 无预览，那会变成像素级操作。

### 5.6 不要做的机制

- 不要加摇杆/多指/技能按钮。
- 不要让镜子需要「旋转到 0.5° 精度」；用吸附/宽容窗口。
- 不要做「随机镜子」；所有关卡必须可解。
- 不要做「必须看广告才能过」的机制。
- 不要做「时间到了直接黑屏」；失败要快、要能立刻重试。
- 不要把所有关都塞进 20 秒；复杂关需要 30–45 秒。

## 6. 时间系统：20 秒怎么加才不劝退

### 6.1 采纳你的规则，但分阶段

你的建议：

> 设置 20 秒的关卡时限，必须在 20 秒内通关。当连接上并触发 3 秒倒计时时，这 20 秒倒计时冻结。

这条规则很好，原因是：

- 它把「找解」变成有时间压力的决策；
- 冻结让玩家在最后 3 秒不用怕超时，3 秒是奖励，不是惩罚；
- 它制造了「最后一秒找到」的高光时刻。

但**不建议所有关都硬性 20 秒**，尤其是 30–60 的镜子/棱镜关：

- 第一次见到新机制，玩家需要观察；20 秒会逼他乱拖；
- 复杂关的解法需要 2–3 步，20 秒不够；
- 失败太频繁会让人退出，而不是「再来一次」。

**V2 的做法：分阶段，不是取消硬计时。**

| 阶段 | 计时 | 作用 |
| --- | --- | --- |
| **学习期（1–20 关）** | 软计时（par）：超时不失败，只影响星级 | 先让新用户学会，不被时间吓走 |
| **主线（21–60 关）** | 硬计时：按复杂度给 20–45 秒，超时失败 | 兑现「有时间压力」的核心体验 |
| **挑战模式（通关后）** | 更紧的 20 秒 / par；双倍光尘 + 排行 | 给老玩家重玩理由，不影响首次通关 |

**21 关起，计时是真的会失败的。** 但失败成本要低：

- 失败后 1 秒内可「重试」，不用回选关；
- 连续失败 3 次，免费给一次方向提示；
- 失败不扣光尘、不扣体力、不弹广告；
- 每关的时间预算按「最短解 + 3 秒保持 + 观察余量」配置，不是拍脑袋 20 秒。

这样既保留了你想要的 20 秒紧张感，又不把第一次见机制的新用户挡在门外。

### 6.2 冻结规则

```
关卡开始 → 计时待机（不扣时）
第一次拖动 → 计时开始
全亮 → 计时冻结 + 3 秒保持开始
保持中断 → 计时恢复（0.5 秒宽限）
保持完成 → 通关，计时停止
面板/广告/后台 → 计时暂停
```

细节：

- **第一次拖动才计时**，不是加载就计时；否则玩家看画面也在扣时间。
- **全亮瞬间冻结**：计时器变蓝、音效「咔」、3 秒环变亮；玩家明确知道「我抢到了」。
- **中断恢复**：给 0.5 秒宽限，避免「刚断就 0.0 秒」的挫败；宽限每关一次。
- **超时失败**：不黑屏；画面定格，显示「差 0.8 秒」，一键重试；不自动弹广告。
- **时间奖励**：剩余时间 × 系数 → 光尘/星级；让「快」有意义，但不用「快」惩罚。

### 6.3 时间预算表

| 关卡类型 | 例子 | 主线硬计时 | 三星 par |
| --- | --- | ---: | ---: |
| 教学 | 1–5 | — | — |
| 静态/多目标 | 6–20 | —（11 起软计时） | 20–25s |
| 过渡/旧机制 | 21–29 | 25s | 18s |
| 单镜 | 30–33 | 20s | 14s |
| 多镜/旋转 | 34–39 | 30s | 22s |
| 棱镜/颜色 | 40–49 | 35s | 25s |
| 移动/组合 | 50–59 | 45s | 32s |
| 终章 | 60 | 60s | 45s |

> 20 秒是「短关」的标准，不是所有关的教条。用户提出 20 秒的意图是「增加紧张感」，不是「让所有关都变成速通」。

### 6.4 UI 与反馈

- 计时器放在屏幕上方，跟关卡号同一行；不要挡住光路。
- 正常：暖白；最后 5 秒：琥珀；冻结：青色 + 「时间冻结」小字。
- 最后 5 秒：每秒一声轻滴，不刺耳；不要红色闪烁。
- 冻结瞬间：3 秒环从光源外圈亮起，音乐加一层。
- 超时：画面轻暗，显示「差 0.8 秒 / 再试一次」；不要「失败」两个大字。

### 6.5 防挫败

- 连续失败 3 次：免费给一次方向提示（不自动播广告）。
- 失败后 1 秒内可点「重试」，不用回选关。
- 挑战模式失败不扣光尘、不扣体力。
- 不做「看广告复活/加时」——那会把失败变成付费点。

### 7.3 星级

- 1 星：通关。
- 2 星：在 par 时间内通关。
- 3 星：par 时间 + 不用提示 + 不重开。
- 星级奖励：5 / 10 / 15 光尘；章节 30 星给宝箱。
- 星级是「重玩理由」，不是「卡关门槛」；不要求三星才能进下一关。

### 7.4 经济平衡

- 日均产出：约 100–150 光尘（含每日、首通、广告 3 次）。
- 第一套皮肤 300：2–3 次 session。
- 第二套 600：约 1 周。
- 不做通胀：新皮肤价格按「日均产出 × 5–7 天」定。
- 广告产出不超过日均 50%；光尘类广告每日 3 次硬上限，全部激励视频每日最多 5 次。
- 防作弊：本地存档；排行榜/云端前不做可交易资产。

### 7.5 为什么这样设计

用户说「每关给用户的正向反馈还不太够」。光尘不是目的，**它是把「通关」变成「到手」的可见反馈**：

- 通关 → 光尘数字跳动 → 商城红点 → 下一个目标；
- 三星 → 额外光尘 → 重玩有意义；
- 章节宝箱 → 大反馈 → 3 分钟节点。

**不做**：插屏、banner、开局广告、失败复活广告、强制广告。

### 8.2 体验规则

- 第一次广告出现在**第 3 关通关后**，不要在 onboarding 里弹。
- 广告按钮必须写清「看广告，光尘 ×2」，不能伪装成普通按钮。
- 广告播放期间：关卡冻结、计时冻结、音乐压低；回来后不发奖两次。
- 无填充/加载失败：按钮变灰，显示「广告暂不可用」，不诱导重试。
- 广告完成才发奖；取消/未看完不发；用令牌防重复。
- 广告不遮挡 3 秒保持；不在保持阶段弹任何东西。

### 8.3 技术流程

```
关卡开始 → 预加载广告
玩家点「×2」→ 生成 reward token → show()
  ├─ onClose(isEnded=true) → 校验 token → 发奖 → 标记已领
  ├─ onClose(false) → 不发奖
  ├─ onError → 显示不可用 → 允许重试一次
  └─ 超时 → 关闭 loading → 不发奖
```

- `adUnitId` 放在 `config/wechat.config.json`；空值时不创建广告实例。
- 每个广告位独立 ID；方便看填充率/eCPM。
- 广告回调绑定「关卡 + 局次」令牌；切关/重开后旧回调作废。
- 广告期间 `game.pause()`；恢复后不补算时间。
- 真机验证：iOS/Android 各一台；无填充、取消、后台切换。

### 8.4 商业化节奏

| 阶段 | 目标 | 广告位 |
| --- | --- | --- |
| 上线首周 | 验证链路，不伤留存 | 只开「光尘 ×2」 |
| 第 2 周 | 验证提示/皮肤试用 | 加「提示」「皮肤试用」 |
| 有数据后 | 优化 eCPM | 加「每日宝箱」；A/B 奖励 |

**先留存，后收入。** 如果广告让 D1 下降，先降频控，不要加更多广告位。

### 8.5 合规与底线

- 广告有明确「广告」标识；奖励写清楚。
- 不诱导点击、不伪装成游戏按钮。
- 不向未成年人做定向诱导；遵守平台广告规范。
- 隐私政策、用户协议、广告 SDK 说明。
- 流量主开通需要条件；未开通时用模拟广告，不假装有收入。

## 9. 沉浸感：让光像一个生命

> 沉浸不是「画面更炫」，而是三件事同时成立：**我能看懂**（能力感）、**我知道下一步**（目标感）、**世界有回应**（惊喜）。V2 的沉浸设计都围绕这三件事。

### 9.1 星座地图：给「下一关」一个意义

- 60 关不是 60 个格子，而是 **6 个星座**，每章一个。
- 每通关一关，点亮一颗星；每章完成，星座连线出现，播放 3 秒无字动画。
- 终章：整个天幕亮起，出现「你点亮了这片天空」。
- 章节地图是主页的第二屏，不是弹窗；玩家随时能看到「还差几颗星」。
- 星座名：初见、微光、镜、棱、时、星。每章一句诗，不强制阅读。

### 9.2 无字叙事

- 开场：一片黑，一颗小光；没有文字，只有一个「开始」。
- 每章：星座亮起，出现一个符号（镜/棱/钟/星）。
- 终章：天空完整，光回到天上。
- 不写长故事、不做对话、不打断关卡；叙事是奖励，不是门槛。

### 9.3 声音：3 秒的和弦

- 每颗水晶亮起加一个音高；全部亮起时，和弦完整。
- 保持 3 秒：低频心跳 + 高频泛音，随进度增强；冻结时音色变亮。
- 通关：和弦解决 + 一声钟；不要爆炸音。
- 音乐分层：章节不同调式；镜章用玻璃质感，棱章用钟琴，时章用脉冲。
- 全部程序化合成，零素材；音量默认保守。

### 9.4 触觉

- 水晶首次亮起：短振动。
- 全亮冻结：两下轻振。
- 保持每秒：极轻脉冲（可关）。
- 通关：一次长振。
- 设置里可关触觉；iOS/Android 差异做降级。

### 9.5 皮肤人格

- 皮肤不只是颜色：拖尾形状、音色、命中粒子的性格。
- 青焰：冷、轻、拖尾长；赤潮：暖、重、光柱粗；星砂：碎光、钟琴音。
- 皮肤描述用一句话人格，不用数值。
- 皮肤试用 24 小时（广告），让玩家先感受再买。

### 9.6 分享、回声、好友

- **分享卡**：星座、关卡、用时、星级、皮肤；「我在 12.4 秒点亮了猎户座」。
- **回声**：记录自己最好一次的轨迹，下次以半透明「影子光」重放；和自己比赛。
- **好友排行**：微信开放数据域，先做好友榜，不做全服榜；只比已通关关卡。
- **异步接力**：好友的「影子光」帮你照亮一个目标（后期实验，不做 MVP）。

### 9.7 每日星图

- 每天 3 个短关（15–25 秒），同一套种子，所有人一样。
- 奖励 60 光尘 + 1 次宝箱；连续 7 天给皮肤碎片/拖尾。
- 分享「今日星图」成绩；不强制。
- 这是最低成本的日活钩子。

## 10. 技术方案

### 10.1 关卡数据模型（v2）

```js
{
  id: 30,
  chapter: 'mirror',
  name: '第一面镜',
  timeLimit: 20,        // 硬计时；0 = 无
  parTime: 14,          // 三星
  tutorial: 'mirror',   // 机制教学
  lights: [{ start, bounds, track }],
  crystals: [{ x, y, side, requires: [0], color: null }],
  mirrors: [{ x, y, w, h, angle, type: 'fixed'|'rotating'|'oneway'|'splitter', speed }],
  prisms: [{ x, y, split: ['red','blue'] }],
  filters: [{ x, y, color }],
  blocks: [...],
  movers: [...],
  runes: [{ x, y, requiresShadow: true }],
  gates: [...]
}
```

### 10.2 光路/反射

- **点光源 + 镜子**：镜像光源 + 可见性测试（路线 A）。
- **光束 + 棱镜**：射线求交 + 反射/折射（路线 B）。
- 最多 3 次反弹；超过吸收。
- 每帧只对「移动的镜子/水晶」重算；静态几何缓存。
- 渲染与判定共用同一条光路结果，避免「画得亮、判定不亮」。

### 10.3 计时器状态机

```
idle → running → frozen → running → won
              ↘ expired
```

- `idle`：加载/教学，不扣时。
- `running`：第一次拖动后。
- `frozen`：全亮，3 秒保持。
- `expired`：超时，失败。
- `paused`：面板/广告/后台。
- 所有状态转移写单测；面板/广告/后台不能扣时。

### 10.4 存档 v4

```js
{
  version: 4,
  unlocked: 20,
  best: { 12: { time, stars, distance } },
  dust: 320,
  skins: ['default', 'azure'],
  equipped: 'azure',
  inventory: { hint: 1, remove: 0, time: 2 },
  daily: { date, streak, claimed },
  ads: { date, count },
  tutorialDone: true
}
```

- v3 → v4 迁移：保留 unlocked/best/skins；新字段给默认值。
- 旧 36 关存档的解锁兜底逻辑保留。
- 货币/道具/星星都要幂等，防止重复领取。

### 10.5 模块拆分

| 模块 | 职责 |
| --- | --- |
| `beam.js` | 光路、反射、镜像光源、命中 |
| `timer.js` | 计时状态机、冻结、暂停 |
| `economy.js` | 光尘、星级、奖励、幂等 |
| `shop.js` | 商品、购买、装备 |
| `ads.js` | 激励视频、预加载、令牌、频控 |
| `analytics.js` | 事件、批量、隐私 |
| `tutorial.js` | 步骤、门控、幽灵手 |
| `chapter.js` | 星座地图、宝箱、进度 |

### 10.6 埋点

必须知道「40–60 秒」花在哪：

| 事件 | 字段 |
| --- | --- |
| `session_start/end` | 时长、关卡数、来源 |
| `level_start` | 关卡、章节、是否首玩 |
| `level_win` | 用时、星级、提示、重开 |
| `level_fail` | 原因（超时/熄灭）、剩余时间、尝试次数 |
| `tutorial_step` | 步骤、是否跳过、耗时 |
| `hint_use` | 类型、是否广告 |
| `ad_show/reward` | 位置、结果、eCPM（后台） |
| `shop_view/purchase` | 商品、价格、余额 |
| `daily_claim` | 连续天数 |
| `chapter_clear` | 章节、星数 |

### 10.7 性能

- 光路最多 3 次反弹；每帧只算可见的移动对象。
- 静态镜面/挡板缓存交点；光源移动时增量更新。
- 避免每帧 new 对象/闭包；用对象池。
- 目标 60fps；低端机 30fps；画质档位可关粒子/拖尾。
- 微信包控制在 500 KB 内（当前 108 KB，V2 代码+关卡预计 < 300 KB）。

### 10.8 测试

- 反射角、镜像光源、遮挡的单元测试。
- 计时器状态机：冻结/恢复/暂停/超时。
- 经济：奖励幂等、迁移、余额不为负。
- 广告：取消/无填充/超时/重复回调。
- 关卡：60 关可解、开局不自动通关、时间预算足够。
- 视觉：截图对比；真机录制。
- 试玩：5–8 人，观察而不是问「好不好玩」。

## 11. 路线图与优先级

### 11.1 Must / Should / Could

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| **Must** | 三步教学、20 秒计时+冻结、光尘、商城、激励视频、30–39 镜 | 直接解决「不会玩/没反馈/没收入/太单一」 |
| **Should** | 星级、章节宝箱、40–49 棱、每日星图、星座地图 | 提升留存与重玩 |
| **Could** | 50–60 时/终章、回声、好友榜、皮肤试用、UGC | 拉长生命周期 |

### 11.2 10–12 周计划

| 阶段 | 时间 | 交付 | 验收 |
| --- | --- | --- | --- |
| 0 原型 | 1 周 | 镜子反射 demo + 计时 demo + 教学 demo | 5 人试玩，能说清怎么玩 |
| 1 接住 | 2 周 | 1–5 关重做、教学、星级、光尘钱包 | 教学完成率 ≥ 85% |
| 2 时间与商店 | 2 周 | 6–29 关计时、商城、广告 2 个位 | 首皮肤 3 次 session |
| 3 镜 | 3 周 | 30–39 关、求解器、校验器 | 10 关可解、可读 |
| 4 棱 | 3 周 | 40–49 关、颜色、色盲模式 | 10 关可解 |
| 5 时与星 | 2 周 | 50–60、星座、每日、埋点 | 上线候选 |
| 6 软启动 | 1–2 周 | 真机广告、A/B、修复 | D1/D7 达标 |

> 如果只能做一半：先做 **1–35 关 + 计时 + 光尘 + 商城 + 广告**，把留存跑通；36–60 放到 v2.1。不要为了「60 关全换」牺牲上线时间。

### 11.3 工作量假设

- 1 名设计 + 1 名 AI 辅助开发（当前模式）；
- 关卡设计是最大成本：镜面 10 关 + 棱镜 10 关 + 时 10 关，约 6–8 周；
- 代码：光路/计时/经济/广告，约 3–4 周；
- 美术：仍以程序化为主，新增镜子/棱镜/星座，约 1–2 周；
- 音频：新增分层，约 3–5 天；
- 测试/调优：2 周。

### 11.4 上线策略

1. 先内测 20 人，重点看教学和镜面可读性；
2. 再灰度 200 人，看 D1/ session；
3. 广告先只开「光尘 ×2」，确认不伤留存；
4. 数据达标后再开提示/皮肤试用；
5. 不要在留存没跑通前加更多广告位。

## 12. 指标与实验

### 12.1 漏斗

```
启动 → 教学第 1 步 → 第 1 关通关 → 第 5 关 → 第 10 关 → 第 20 关 → 第 30 关 → 第 60 关
```

每步看流失；重点：

- 教学第 1 步流失（不会拖）；
- 第 1 关到第 2 关（没懂目标）；
- 第 5 关到第 6 关（第一次计时）；
- 第 20 关到第 21 关（机制切换）；
- 第 29 关到第 30 关（镜子教学）。

### 12.2 核心指标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 平均 session | 3–5 min | 主指标 |
| 单 session 关卡数 | 5–8 | 节奏 |
| 教学完成率 | ≥ 85% | onboarding |
| D1 | ≥ 35% | 留存 |
| D7 | ≥ 12% | 留存 |
| 第 10 关到达率 | ≥ 60% | 内容 |
| 首皮肤获得 | ≥ 40%（3 次 session） | 元系统 |
| 广告观看率 | 15%–25% | 商业化 |
| 关卡失败率 | 20%–35% | 难度 |
| 重试率 | ≥ 40% | 粘性 |

### 12.3 A/B 实验

| 实验 | A | B | 看什么 |
| --- | --- | --- | --- |
| 教学 | 文字提示 | 幽灵手 + 门控 | 教学完成率、第 2 关到达 |
| 计时 | 全程硬 20s | 1–20 软 + 21–60 硬（30–45s） | 失败率、重试率、留存 |
| 货币 | 首通 10 | 首通 20 | 首皮肤时间、session |
| 广告 | 通关 ×2 | 每日宝箱 | 观看率、D1 |
| 镜面 | 虚线预览 | 无预览 | 通关率、挫败反馈 |

### 12.4 止损线

- 教学完成率 < 60%：回滚教学，重新做；
- 第 5 关到达率 < 50%：难度/计时有问题；
- D1 < 25%：元系统或广告伤留存；
- 镜子关失败率 > 50%：可读性失败，切光束模式；
- 广告导致 D1 下降 > 3 个百分点：降频控。

**V2 不是把 60 关变难，而是把「找位置」变成「找路径、找时机、守住光」，再用教学、星级、光尘、商城、星座和广告把每一次「我做到了」接住。**
