# 关卡设计：60 关怎么排

> 关卡数据由 `scripts/gen-levels.mjs` 生成，`scripts/validate-levels.mjs` 校验，`scripts/audit-levels.mjs` 审查。
> 这里只记录设计意图和分组，不贴坐标。

## 1. 六个阶段

| 组 | 关卡 | 教学重点 | 新增的「问题」 |
| --- | --- | --- | --- |
| 基础 | 1–6 | 单光源、单目标、影子、3 秒 | 光要站在哪？ |
| 静态遮挡 | 7–12 | 2–4 个目标、挡板、窄缝 | 怎么同时照顾多个目标？ |
| 移动遮挡 | 13–18 | 周期性移动、轨迹可预判 | 什么时候站进去？ |
| 干扰角色 | 19–24 | 会胀大缩小的游走体、前摇 | 什么时候躲？ |
| 双光源 | 25–30 | 两盏灯、分工、双灯同照 | 先摆哪一盏？ |
| 双侧水晶 | 37–60 | 上下两面墙、同一 3 秒窗口 | 怎么折中？ |
| 组合 | 31–36、49–60 | 机制叠加 | 先规划，再执行 |

> 第 31–36 关在数据上是「右侧单墙 + 组合机制」，第 37 关起进入双侧。所以 31–36 不是双侧，别被关卡号误导。

## 2. 机制表

| 机制 | 出现关卡 | 说明 |
| --- | --- | --- |
| 静态遮挡 | 1 起 | 挡板投在墙上的影子随光源距离放大 |
| 多目标 | 3 起 | 一颗水晶一条缝，彼此挤位置 |
| 移动遮挡 | 13–18、31–36、45–48 | 周期性往返/绕圈，轨迹虚线画出，可预判 |
| 干扰角色 | 19–24、33–36、53–56 | 会胀大缩小的游走体，胀大前有前摇光圈 |
| 双光源 | 25–30、31、34、49–52、57、59、60 | 两盏灯各自负责一部分水晶，点哪盏拖哪盏 |
| 双侧水晶 | 37–60 | 上下两面墙都有目标，必须同一个 3 秒窗口里同时满足 |
| 需两盏同照 | 27 | 水晶下面两个点，都亮才算满足 |
| 组合 | 49–60 | 双灯 + 双侧 + 移动 + 干扰叠加 |

**双光源 ≠ 双侧水晶**：前者是场上有两盏可拖的灯，后者是两面墙都有目标。第 49 关起两者叠加。

## 5. 难度控制

- **不用手速制造难度**：不加快移动速度、不缩小判定范围、不做像素级操作。
- **解区面积有下限**：校验器检查解区不能小到手机点不中；第 37 关故意宽容，第 38 关起收窄。
- **动态关留 4.2 秒干净窗口**：实际通关 3 秒，留 1.2 秒容错。
- **组间缓冲**：37–38、45、53 是「先看懂再动手」的关。
- **开局不能自动通关**：起始位置必须凑不出 3 秒。

## 6. 怎么加第 61 关

见 [LEVEL-EXTENSION.md](audit/LEVEL-EXTENSION.md)。要点：

1. 在 `scripts/gen-levels.mjs` 的 `RECIPES` 末尾加配方；
2. `npm run gen` 生成；
3. `npm run validate` 校验；
4. `npm test` 回归；
5. 更新 `CONTENT_VERSION`；
6. `npm run build:wechat` + `npm run verify:wechat`。

不要手改 `src/levels.js`；不要为了通过旧断言而改已有关卡。
