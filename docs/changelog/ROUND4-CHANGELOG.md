# 第四轮：拉开上下光柱 + 第 1–3 关重做

> 2026-10-26。真机项未测（本机无设备）。

## 一、上下光柱拉开

**根因**：玩法带的缩放被"沿墙方向的内容跨度"锁死。原先可拖拽范围固定成整面墙（y 220..1060，840），
任何等比布局都只能得到 720/944 ≈ 0.76 的缩放，两墙距离固定在 388。

**做法（三层叠加）**：

1. **沿墙压缩**（`levels-live.js`，`WALL_SQUASH = 0.75`）：把每关沿墙方向的坐标按 0.75 压缩。
   仿射变换保持共线与相交，遮挡/点亮关系逐点不变，但沿墙跨度从 840 降到 630。
2. **按内容收紧可操作范围**（`src/fit.js`）：拖拽范围从"整面墙"改成"本关内容 ±96"，并夹在原边界内；
   光源起点同步夹进新范围。
3. **按内容框定布局**（`src/layout.js`）：缩放 = min((720-80)/内容长边, 可用高/内容短边, 1.22)，
   左右各留 40 边距，玩法带在 HUD 与读秒条之间居中。

**效果（逻辑坐标，720×1280）**：

| 指标 | 之前 | 现在 |
|---|---|---|
| 双侧关两墙距离 | 388（固定） | 469–509，平均 **480**（+24%） |
| 单侧关玩法带高度 | 448（固定） | 394–581，平均 **489** |
| 手机上（844 高）两墙距离 | 256 CSS | **317 CSS**（+24%，最大 +31%） |

单侧目标关仍是单侧结构；没有新增目标或改成双侧。

## 二、第 1–3 关重做

审查发现：三关的解都在 x 150–200、y 620–860 一带，都是"从右下往左上挪一点"，只是水晶数量不同。

| 关卡 | 原来 | 现在 | 玩家要换的动作 |
|---|---|---|---|
| 第 1 关 | 水晶 y=470，解 (200,780) | **保持** | 直接拖到水晶方向，建立"拖光→亮"的直觉 |
| 第 2 关 | 水晶 y=430，解 (160,860) | 水晶 **y=1000**，解 **(150,320)**，挡板加高到 260 | 目标在墙的另一端，必须**远离水晶、往上走**，还要避开高挡板的影子 |
| 第 3 关 | 水晶 340/900，解 (180,620) | 水晶 **300/980**，解 **(250,640)**，挡板 160×120 | 两颗目标一上一下，要找一个**同时照顾两端**的位置，而不是重复第 1/2 关的站位 |

改动进入 `scripts/gen-levels.mjs` 的 RECIPES，用 `node scripts/gen-levels.mjs --write` 重新生成；
重生成后**只有第 2、3 关数据变化**，其余 58 关逐字节未变（已用旧快照比对）。

## 四、已知取舍（必须知道）

1. **距离挑战的"理论最优"被隐藏**：压缩改变了路径长度，旧的 `distance.optimal` 不再可比，
   本轮把 `distance` 置空，分享卡不再显示"理论最优"。要恢复需要按新几何重算参考距离。
2. **只重做了第 1–3 关**。其余关卡的"解法相似"问题**没有系统解决**，只是被布局变化部分缓解。
3. 真机未测：两墙拉开后的手指遮挡、拖拽舒适度、长屏/刘海机的空间感。
