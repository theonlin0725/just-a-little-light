## 一、审查方法（不是看截图）

新增 `scripts/audit-levels.mjs`，对象是**运行时关卡**（镜像 → 沿墙压缩 → 边界收紧之后），逐关计算：

- 机制标签（单/双光源、单/双侧、移动、干扰、双照）
- **可行解区**：6px 网格 + 保持 3 秒判定，取最大连通区，记录面积、连通块数、中心
- **可达距离**：起点到解区的实际可走距离（BFS）
- **动作向量**：起点 → 解区中心的单位方向
- **保持窗口**：在解区中心能连续满足的最长时间
- **相邻相似度**：动作向量余弦 + 相邻解区中心距离

输出：`docs/LEVEL-AUDIT.md`（60 行，每关一行）。

> 局限：双光源关只取第 1 盏灯的方向，不能反映"分工/顺序"差异；
> 因此 25–36、38–53 里被标记的相似对需要人工判断，本轮的相似度阈值只用来筛查单灯关。

## 三、距离挑战回归修复

上一轮把运行时 `distance` 全部置空，隐藏了参考值也绕过了验证。本轮修复方式：

1. **把沿墙压缩移进生成器**（`scripts/gen-levels.mjs` 的 `squashLevel`），在**算距离之前**执行，
   距离因此基于最终几何。
2. 运行时不再二次压缩（`levels-live.js` 只做镜像 + 边界收紧）。
3. 恢复 `distance` 字段与分享卡展示，标签从"理论最优"改成**"参考距离"**（离散网格近似，不宣称严格最优）。
4. `npm run validate` 恢复对 5/9/12 的距离校验并通过：
   - 第 5 关 196.3 / 第 9 关 185.0 / 第 12 关 274.6（最终几何，网格步长 5）。
5. 旧成绩：存档里按关卡 id 记 `best`，未清空；只在新旧几何不可比时**不展示旧距离对比**，解锁进度保留。
